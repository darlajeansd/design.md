## 2025-02-27 - Mitigating Code Injection via `node:vm`
**Vulnerability:** Arbitrary code evaluation via `new Function` in MDX compilation (`packages/cli/src/linter/spec-gen/compiler.ts`).
**Learning:** `new Function` directly executes code in the global scope without isolation, making it dangerous for evaluating untrusted MDX expressions. The codebase memory notes that while `node:vm` provides basic isolation, it is *not* a secure sandbox and can be escaped. Furthermore, evaluating expressions requires care: wrapping an expression like `{a: 1, b: 2}` in parentheses `(${expr})` will crash on empty expressions `{ }` or comments `{/* comment */}`. A better approach is wrapping in an IIFE `(function() { return ${expr}; })()`. For performance across multiple AST nodes, use `vm.createContext` once and `vm.runInContext` rather than `vm.runInNewContext`.
**Prevention:** Avoid `new Function` for arbitrary evaluation. Use `node:vm` as a basic isolation layer, remembering to wrap expressions in an IIFE `(function() { return ${expr}; })()` and pass a shallow copy of the scope `{ ...scope }` via a reused context `vm.createContext({ ...scope })`. For true security against untrusted code, use an AST-based evaluator or a hardened sandbox like `isolated-vm`.
