## 2025-02-18 - Fix code injection via new Function
**Vulnerability:** Code injection via untrusted MDX expressions. The application used `new Function(...Object.keys(scope), \`return ${expr}\`)` to evaluate user-provided Markdown/MDX text, which directly exposes the Node.js global scope and leads to RCE if the markdown is not perfectly trusted.
**Learning:** `new Function` provides absolutely no isolation. We mitigated this by replacing it with `node:vm` (`vm.createContext` and `vm.runInContext`). While `node:vm` prevents direct access to the global object and provides basic isolation, it is heavily caveated. Crucially, NEVER document or rely on `node:vm` as a "secure sandbox" or primary security boundary against untrusted code (it is an easily escapable anti-pattern).
**Prevention:** Avoid `new Function` or `eval()` for code execution. Use `node:vm` cautiously with `vm.createContext()` (re-using contexts when practical) and evaluate expressions as IIFEs. For true untrusted code execution, use an AST-based evaluator or a hardened sandbox like `isolated-vm`.
