## 2025-02-14 - Arbitrary Code Execution in MDX Compilation
**Vulnerability:** The MDX compiler (`packages/cli/src/linter/spec-gen/compiler.ts`) used `new Function(...Object.keys(scope), \`return \${expr}\`)` to evaluate user-provided MDX expressions. This is essentially an `eval()` call that executes code in the global Node.js context, leading to critical RCE vulnerabilities.
**Learning:** This existed because `new Function` is a common, but insecure, way to quickly evaluate string expressions in JavaScript when compiling templates or markdown.
**Prevention:** Replaced `new Function` with `node:vm`'s `runInNewContext()`. While not a perfect sandbox, it isolates the execution context from the global scope, mitigating straightforward RCE vectors. Wrapped the expression in parentheses `(${expr})` to ensure it evaluates exactly like the original `return ${expr}` (especially crucial for object literals), and passed a shallow copy of the scope `({...scope})` to prevent state leakage. Add a comment that `node:vm` should not be relied upon as a secure sandbox against truly untrusted code.
