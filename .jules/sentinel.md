## 2025-02-27 - Replace `new Function` with `node:vm`
**Vulnerability:** Code injection vulnerability in MDX expression evaluation. The `compileMdx` function uses `new Function(...Object.keys(scope), \`return ${expr}\`)` to evaluate MDX expressions. This allows arbitrary JavaScript execution with access to the global scope (like `process.env`, `require`, etc) if the input MDX is untrusted.
**Learning:** Evaluating untrusted expressions via `new Function` is a major security risk as it creates a function with global scope access. `node:vm`'s `runInNewContext` offers basic isolation, preventing access to the global scope unless explicitly provided in the context. While not a perfect sandbox (like `isolated-vm`), it prevents easy arbitrary command execution and environment variable leakage for simple expression evaluation. Be careful not to use `vm.runInContext` on an in-place mutated scope per previous memory hints, and also be aware that MDX expressions with object literals like `{a: 1}` can cause `SyntaxError` in `runInNewContext` if not wrapped or handled carefully, but the current MDX test cases all pass with `vm.runInNewContext( \`(${expr})\`, sandbox )`. The tests show `({1 + 1})` -> `((1 + 1))` which is perfectly valid syntax, `({ITEMS.map(...)})` -> `((ITEMS.map(...)))` which is perfectly valid, and `{colors.primary}` in code block -> `((colors.primary))` perfectly valid.
**Prevention:** Avoid `new Function` and `eval` for untrusted code execution. Use `node:vm` for basic context isolation. Note that `node:vm` is NOT a secure sandbox, but it provides basic isolation that fixes the immediate `new Function` risk.
