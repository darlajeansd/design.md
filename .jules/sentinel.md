## 2024-05-24 - MDX Compiler Code Execution Sandbox Escape Prevention
**Vulnerability:** The MDX compiler (`packages/cli/src/linter/spec-gen/compiler.ts`) was using `new Function()` to evaluate MDX expressions, which executes code within the application's global scope, presenting an arbitrary code execution vulnerability.
**Learning:** `new Function` provides no isolation for code evaluation and can easily lead to state leakage or complete sandbox escape. Using `node:vm` is preferred for executing untrusted strings. The `vm.runInContext` requires evaluating a string as an IIFE (e.g. `(function() { return ${expr}\n; })()`) instead of wrapping in parentheses to avoid `SyntaxError` on empty expressions, and a shallow copy of the scope (`{ ...scope }`) should be passed to prevent state leakage. `vm.createContext` should be called once outside the loop for performance across multiple nodes. Note that `node:vm` is not a strong security sandbox, but it provides basic isolation over `new Function`.
**Prevention:** Avoid `new Function` for code evaluation. Instead, utilize AST-based evaluators or sandboxing mechanisms like `node:vm` properly (or stronger alternatives like `isolated-vm` for untrusted code execution).
